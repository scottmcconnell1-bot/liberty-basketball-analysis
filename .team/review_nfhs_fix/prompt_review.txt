2. If yt-dlp exits non-zero but the final file (or yt-dlp's <name>.temp.mp4 fixup output) exists:
   - leftover .temp.mp4 that is a good MP4 -> replace the final file with it;
   - final file is a good MP4 (ffprobe mp4/mov + video stream + duration>0 + last 5 s decodes) -> accept;
   - final file is a readable video but not MP4 (raw MPEG-TS) -> ffmpeg -c copy -bsf:a aac_adtstoasc
     +faststart remux, verify, replace (retry while Windows holds a lock);
   - otherwise -> error as before, now with the log path.

   Reasoning: yt-dlp only renames .part to the final name after all fragments are downloaded, so an
   existing final file means the download finished and a post-step failed.
