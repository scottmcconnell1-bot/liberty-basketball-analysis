### G2 Pooling dilution — real; sampling already pinned without saying so
r2plus1d ends in global avg pool (`avgpool` in checkpoints). Window is **6.88 s**; old dense shot window is **~2.48 s** (~36% of frames). Dilution of make/miss / ordinary-shot cues is a real risk.

### G3 Confound — same failure mode as 52c F2; under-disclosed
**Proven** from clips7a labels: class-0 counts **gvg 145 / rimrock 241**. Class-0 with a **shot (y∈{1,2}) within +6 s**: **gvg 17 (11.7%)**, **rimrock 18 (7.5%)**. Those class-0 clips will now **contain a later shot** in the crop → risk of teaching “shot later in clip → shot” and raising false shots — same structural confound as the noisy seq flag.

Spec §1.7 covers first-shot→putback, not this reverse case. Disclose it; fail→stop still OK.

### G4 Dropout — spec is wrong; R4 had Dropout
**Proven:**
- Pre-52c Cursor review: head was `Dropout(0.5) → Linear(512, 3)`.
- 52c prereg: `nn.Dropout(0.5) before the head UNCHANGED`.
- R4/ens51/final51 checkpoints: keys `fc.0`, `fc.1.weight` / `fc.1.bias` = `Sequential(Dropout, Linear(512,3))`.
- Current code (52c): `pool_drop` + `Linear(513,3)`.

52d’s “R4 has no dropout; 52c added Dropout for seq” is **false**. Pin head exactly as R4: **`Dropout(0.5) → Linear(512, 3)`** (no seq). Bare `Linear(512,3)` is a recipe change.
