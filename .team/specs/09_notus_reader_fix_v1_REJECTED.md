## Diagnosis

**Root cause**: The `_red_mask` imported from `scoreboard_clock.py` uses HSV thresholds (S > 90, V > 120, red hue ranges) tuned for the 1920×1080 Mustangs board. The Notus 1280×720 board's red digits are dimmer — lit segments peak at V ≈ 50–120 — so the mask misses the tens digits entirely (V ≈ 10–50 when lit, V ≈ 10 when blank) and often misses ones digits in early frames.

**Why the fitted geometry is wrong**: `fit_notus_segments.py` used the old `_red_mask` (V>120) on non-gate frames. That mask only caught the brightest cores of lit segments, so the "dark hole" detection found gaps that don't align with the true segment boundaries under a proper mask. The saved `notus_segment_geometry.json` therefore defines core regions that are fully lit for BOTH on and off segments when the new mask is used.

### 1. Add Notus-specific mask to `scoreboard_clock_720p.py`
```python
def _notus_red_mask(crop: np.ndarray) -> np.ndarray:
    """Red mask tuned for Notus 720p board: lower S/V thresholds for dimmer digits."""
    import cv2
    hsv = cv2.cvtColor(crop, cv2.COLOR_BGR2HSV)
    low = cv2.inRange(hsv, (0, 50, 50), (12, 255, 255))
    high = cv2.inRange(hsv, (165, 50, 50), (180, 255, 255))
    mask = cv2.bitwise_or(low, high)
    return cv2.morphologyEx(mask, cv2.MORPH_CLOSE, np.ones((3, 3), np.uint8))
```
